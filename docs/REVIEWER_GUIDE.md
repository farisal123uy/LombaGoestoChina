# Guardian Wallet — reviewer quick start

## Access

- Interactive application:
  https://preview-95c94201191f7206.up.railway.app/review
- Recorded evidence:
  https://preview-95c94201191f7206.up.railway.app/evidence
- Readiness (no login):
  https://preview-95c94201191f7206.up.railway.app/api/review/ready

The team supplies a **reviewer access code** privately. The team-local file
`.local/linux-review/reviewer-link.private.txt` contains the full access link with a
URL fragment; it is excluded from the source archive. Do not publish a model API key
or reviewer access code in source/evidence. The fragment is consumed in the browser
and removed from the address bar; session API requests use a short-lived capability.

No MetaMask, personal funds, model installation or judge-owned API account is needed.

## Try the implemented task

1. Open `/review`, use the private access code and select **Start private review
   workspace**. Initialization usually takes tens of seconds; allow up to two minutes.
2. In **Your wallet, with Astra**, inspect the asset overview and wallet policy risk.
   Asset/risk numbers are computed from contract/task state, not generated by the model.
3. Enter:

   > Rent a 1 MB database for 1 hour. Pay only the authenticated catalog invoice
   > within my existing wallet policy.

4. Choose **Ask wallet assistant**. Review the draft, authenticated recipient/amount,
   budget and risk checks. A draft is not submitted automatically.
5. Choose **Queue reviewed payments**, then **Start agent** if scheduling is paused.
6. Wait for the task to become **completed**, select it and inspect the confirmed
   escrow-lock/release operation hashes and signed provider namespace. Funds are
   locked in Guardian first, then released after provider attestation; if the provider
   does not deliver before the escrow deadline, timeout recovery returns funds on the
   isolated fork.
7. Choose **Verify database probe**. Enter a key/value and choose **Write & read back**.
8. Close the workspace when finished. A new workspace has its own wallet/database.

The UI supports English and Indonesian task instructions. Unsupported actions such
as arbitrary-recipient transfer, swap or changing owner authority are not available.
Try a request to bypass the wallet policy and inspect the result; prompt refusal alone
does not grant or prove contract authority.

## Interpreting results

- Inference is the real hosted GPT-OSS 120B API configured on the server.
- Contracts and settlement are actual Kernel/EntryPoint/Guardian code, executed on
  an **isolated Base Sepolia fork**, with disposable token/native assets.
- Sandbox hashes do not exist on the public explorer. The historical **public**
  procurement transaction is linked separately in the evidence page.
- `planned`/`queued` is not payment confirmation. `paid` proves settlement; `completed`
  additionally requires delivery signature/probe verification at that time.
- The session lasts 15 minutes. Namespace rental terms are part of the sandbox
  catalog; closing/expiry discards that workspace earlier than a one-hour offer.
  Completion is not a claim of uninterrupted service for the whole advertised period.

## Quota and availability

The host allows one active workspace initially. If occupied, wait for it to be closed
or expire. Free AI quota may return a visible rate-limit error; no paid fallback or
automatic billing activation is performed. Refresh/retry the same request after the
reported wait; do not create a second payment to work around an unknown operation.

The team must monitor the Free/Trial hosting entitlement and credits throughout
judging. Public HTTPS browser verification and three China endpoint probes were
recorded; this is not an uptime SLA or a test on the judge's exact network.

For a read-only operational check from the team's source workspace:

```powershell
npm.cmd run release:readiness
```

This validates the recorded deployed build, current public readiness and rejected
unauthorized access; it does not create a workspace, infer with the model, pay an
invoice or activate billing. Short hosting transition errors are recorded and bounded
read-only rechecks are attempted. A failed check remains a failure report.
